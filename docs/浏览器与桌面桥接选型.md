# 浏览器与桌面桥接选型

## 结论

psyclaw 不重写浏览器自动化或桌面控制 runtime，统一通过现有 MCP adapter 接入，默认保持 discover-only。

| 能力 | 推荐实现 | 适用范围 | 当前策略 |
| --- | --- | --- | --- |
| 浏览器网页、表单、页面提取 | Microsoft Playwright MCP | 本地浏览器、可复现网页任务 | 首选候选；优先 stdio；可选 Chrome 扩展连接已有标签页 |
| 长耗时或云端浏览器 | Browserbase / Stagehand MCP | 需要持久浏览器、托管会话或异步任务 | 后置 opt-in；需要单独记录网络、账号和费用边界 |
| 本机桌面窗口、截图、键鼠 | Orca computer-use | Windows 桌面应用和浏览器窗口 | 由宿主 Orca 提供，不复制进 psyclaw core |
| 原生跨平台计算机控制 | computer-use-mcp | Windows/macOS/Linux 全桌面控制 | 高风险候选；必须显式权限、窗口范围和人工确认 |

## 为什么首选 Playwright MCP

- 有官方维护的 Playwright MCP server。
- 工具返回结构化网页状态，不需要 psyclaw 自己解析截图坐标。
- 可以使用隔离浏览器，也可以通过 Chrome 扩展连接当前登录标签页。
- 现有 `StdioMcpIntegration` 已经覆盖进程、环境变量、超时、allowlist、effect 和 receipt，接入只需要新增配置和信任记录。

## 不默认启用的原因

浏览器登录态、Cookie、机构 VPN、下载全文和表单提交都属于高敏感副作用。发现、健康检查和工具清单可以自动完成；实际导航、登录、下载、提交和桌面控制仍需项目级审批，并写入 receipt。

## 预留接口

第一阶段只需要支持 MCP stdio：

```json
{
  "id": "playwright-mcp",
  "transport": "stdio",
  "command": "npx",
  "args": ["@playwright/mcp@latest"],
  "trust": "discover-only"
}
```

Browserbase 的 hosted Streamable HTTP 和 SSE 不应伪装成 stdio；如果将来接入，应新增明确的远程 transport、网络域名 allowlist、成本 receipt 和凭据隔离。
