# 文档规范（Document Convention）

> 本文件是 psyclaw 项目内**文档生成与存放位置**的约定真源（0.29+）。
> panel 的文档识别与手稿发现按此约定工作。

## 1. 目录约定

```
项目根/
├─ psyclaw.md            上层约定与流水线说明（人可读）
├─ paper/                唯一手稿区（论文/报告正文）
│  ├─ *.md               可编辑 Markdown 源
│  ├─ *_APA7.docx        排版导出
│  └─ archive/           历史版本
├─ literature/           参考文献全文
├─ data/
│  ├─ raw/               原始数据（只读；指纹仅防篡改）
│  └─ clean/             清洗后可分析数据
├─ analysis/
│  ├─ scripts/           可复现脚本
│  ├─ configs/           分析规格 / 变量映射
│  ├─ results/           数值与表图产物
│  ├─ outputs/           兼容旧路径的输出
│  └─ HANDOFF.md         分析 → academic 交接
├─ notes/                可选轻笔记（非手稿；手稿只认 paper/）
├─ outputs/              杂项工作流产物（尽量少用）
└─ .psyclaw/             系统区
   ├─ project.json
   ├─ verify-checklist.json   人确认清单
   ├─ notes/             系统交接 HANDOFF
   ├─ skills/ / agents/  项目级能力
   ├─ data/raw/          旧路径（仍只读保护）
   ├─ ars-runs/          ARS 审稿桥接痕迹
   └─ evidence/claims/…  账本（内部；不作「学术已核验」证明）
```

## 2. 模式与流水线

Shift+Tab：`chat` → `analysis` → `academic`。

软流水线：建仓 → 澄清 → 审查 → 方案 → 审查 → 分析 → 分析报告 → 审查 → ARS（每阶段审查）。

- 第一要务：把结果跑出来（不硬阻断）
- 第二：AI 语义核查核心字段 + `/verify` 人确认
- 指纹：只保护 raw 等关键边界，不当学术过关

## 3. 手稿发现顺序（/api/manuscript）

1. `paper/` 下 `.md`（优先名称含 手稿/论文/初稿/draft/manuscript）
2. 兼容：`notes/manuscript.md`（旧项目）
3. 回退：`analysis/` 报告与 `.psyclaw/notes/HANDOFF.md`

## 4. 生成端要求

- 手稿只写 `paper/*.md`
- 统计结果写 `analysis/results/` 或 `analysis/outputs/`，脚本写 `analysis/scripts/`
- 切到 academic 前更新 `analysis/HANDOFF.md`
- 不要改写 `data/raw/` 或 `.psyclaw/data/raw/`
