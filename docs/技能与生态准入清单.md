# 技能与生态准入清单

## 1. 准入状态

每个 Skill、MCP 或 Plugin 都必须有 descriptor。建议状态：

`discovered -> inspected -> available -> enabled -> verified`

异常状态：`degraded`（依赖/合同不完整）、`blocked`（明确禁用或路径越界）、`archived`。发现和启用由用户选择；启用不等于学术质量或来源内容已经核验。

最小 descriptor：

```json
{
  "id": "nature-reader",
  "version": "source-ref-or-package-version",
  "sourceRef": "url-or-local-path",
  "resolvedPath": "absolute-path-after-resolution",
  "sha256": "...",
  "license": "MIT|unknown|...",
  "licenseStatus": "verified|unknown|incompatible",
  "dependencyStatus": "ready|missing|incomplete",
  "evidenceLevel": "core|verified|unverified",
  "risk": ["read", "network", "write"],
  "trust": "discover-only|approved|blocked",
  "enabled": false
}
```

本地 symlink 必须同时记录逻辑路径和 resolved path；不能把符号链接目录误当作可分发源码。安装/更新可记录 lock、来源 ref、哈希和 SBOM 作为审计信息，但缺失这些字段不阻断用户选中的 Skill。

### 1.1 可验证的 manifest/SBOM 合同

准入不是“字段存在”检查。M1 采用版本化 JSON Schema（未知字段拒绝）和 CycloneDX JSON 1.5 作为 SBOM 最小格式：

```json
{
  "schemaVersion": "psyclaw/manifest/v1",
  "id": "nature-reader",
  "version": "0.1.0",
  "source": {"kind": "git", "ref": "<commit-or-tag>", "url": "<url>"},
  "contentSha256": "<sha256>",
  "license": {"spdx": "MIT", "evidenceRef": "LICENSE"},
  "dependencies": [{"name": "<name>", "version": "<exact>", "license": "<SPDX>", "sha256": "<optional>"}],
  "sbom": {"format": "CycloneDX", "specVersion": "1.5", "path": "sbom.cdx.json", "sha256": "<sha256>"},
  "capabilities": ["read"],
  "trust": "discover-only",
  "contract": {"inputSchema": "<ref>", "outputSchema": "<ref>", "fixtures": ["<case-id>"]}
}
```

安装时向用户展示来源、版本和已知依赖信息；缺少许可证、哈希或依赖说明时给出提示，由模型在安装和使用过程中补充或解释，不因此阻断 Skill。路径越界、符号链接写入和凭据访问仍然拒绝。

`SkillRegistry` 允许用户明确选中的 Skill 直接进入运行时；许可证、依赖、哈希和正文预检仅用于发现提示。明确禁用、路径越界、符号链接和凭据相关操作仍可阻断。

## 2. L0: psyclaw 自研核心（首期）

只保留四个默认 Skill，全文按需加载：

| Skill | 作用 | 必须守住的边界 |
|---|---|---|
| `research-intake` | 研究目标、范式、范围、伦理与输出卡 | 缺关键输入就暂停，不替用户决定研究问题 |
| `evidence-capture` | 本地材料/DOI 元数据导入、来源状态、SHA | 不把摘要当全文，不猜字段，不默认联网 |
| `citation-audit` | Claim-Evidence 映射、引用完整性、冲突披露 | 题名相关不等于支持；无法验证即 `uncertain/FAIL` |
| `research-brief` | 将已验收证据汇成短研究简报 | 不添加无证据事实，不生成伪统计结果 |

`analysis-plan` 可在 M2 后作为第五个 core skill；统计计算仍外部委托。

## 3. L1: 按需学术包

以下是路由目录，不是默认内置正文。纳入前必须完成许可证、依赖闭合、来源 ref/SHA、prompt injection 检查和最少一个本地 fixture。

| 包/能力 | 适用场景 | psyclaw 处理 |
|---|---|---|
| `researchwrite` 原则 | proposal-first、证据先于文字、章节契约 | 抽取原则并自研实现；当前 references 不完整，标 `degraded` |
| `deep-research` | 多源研究、证据等级、矛盾披露、DA/伦理 | 抽取角色和门禁；不常驻其 13-agent 团队 |
| `academic-paper-strategist` + `academic-paper-composer`（lishix520/academic-paper-skills） | 大纲策划与分章写作查漏补缺 | **默认安装**；接在核心 intake/证据门之后，不伪造引用与结果 |
| `academic-paper` 旧包 / 其它 composer | 大纲、写作、格式转换 | 仅在输入和共享合同闭合后启用；依赖缺失时标 degraded |
| `academic-paper-reviewer` / `nature-reviewer` | 同行评审/复审 | 二选一按用户目标路由，不合并成更大评审群 |
| `nature-reader` | source-grounded 全文阅读 | 要求原文/译文/source_map/术语账本；缺全文不降级 |
| `nature-academic-search` | 多源检索 | 依赖和 API 配置预检；社会科学 profile 需去英语/影响因子偏差 |
| `nature-citation` + `nature-ref-verifier` | 引文支撑与字段核验 | 先 Claim→source；`nature-ref-verifier` **默认安装**做 DOI/作者/年份多源核验 |
| `nature-statistics` | 报告透明性 | 只审计报告，不替代真实统计计算 |
| `nature-figure` | 科研图与视觉 QA | **默认安装**；Python/R backend 独占、数据完整性门；managed install 会拉取上游图表示例资源 |
| `nature-polishing` | Nature 风格终稿润色 | **默认安装**；不得改主张、引用、数字或结构 |
| `nature-data` | FAIR/数据可用性声明 | 禁止编造 DOI、repository、license、embargo |
| `nature-response` | 回复真实审稿意见 | 只接收用户提供的意见和证据 |

## 4. L2: 外接 Plugin/MCP/应用

默认由用户选择是否启用；管理信息缺失时提示并交由模型补充，不阻断正常使用：

- 合法全文获取、浏览器桥、Zotero、Paper Search MCP
- OpenKB/Corpus2Skill、MentorForge/Nuwa、团队知识编译
- CodePivot、Feishu/cron、PPT/专利工具
- SPSS、R、Stata、Mplus、Python 统计后端

机构认证必须由用户在可见浏览器中完成；psyclaw 不保存或转发凭据，不绕过付费墙。人物/导师 Skill 只能描述公开材料支持的时间截面和不确定性，不生成“数字替身”。

## 5. 路由优先级

采用“最窄匹配优先”，避免同一请求同时装载多个大包：

1. 全文阅读 -> `nature-reader`；只有“概括”才考虑通用 summarize。
2. 文献发现 -> `nature-academic-search`/受信 MCP；持续订阅才用 literature pipeline。
3. 引文支撑 -> `nature-citation`，随后 `nature-ref-verifier`。
4. 研究设计/写作 -> `researchwrite` 骨架；默认查漏补缺用 `academic-paper-strategist`（大纲）与 `academic-paper-composer`（分章写作），合同未闭合时不加载。
5. 审稿 -> `academic-paper-reviewer` 或 `nature-reviewer` 二选一；真实意见回复 -> `nature-response`。
6. 统计/图 -> `nature-statistics`/`nature-figure`（figure 默认安装），计算委托外部 backend；终稿润色用 `nature-polishing`。
7. 下载、Zotero、知识蒸馏和面板 -> 仅在明确意图时启用。

默认工作流查漏补缺（`/init`、会话启动时 best-effort 安装，离线不阻断）：`nature-figure`、`nature-ref-verifier`、`nature-polishing`、`academic-paper-strategist`、`academic-paper-composer`。它们不替换核心 intake/证据/Claim 门禁；缺失时继续核心路径并明示未运行该 filler。

国内镜像：若通过 `registry.npmmirror.com` 等国内 npm registry 安装 PsyClaw，或设置了 `PSYCLAW_GITHUB_MIRROR`，上述默认 filler 的 GitHub 拉取会自动走同一套镜像路由（源码归档优先，再镜像 git；清单仍钉官方 URL + commit）。已配置 `HTTP(S)_PROXY` / `ALL_PROXY` 时仍走代理访问官方 GitHub，不被镜像改写。

冲突、重名、版本不一致或来源不明时显示诊断并停止自动选择。

## 6. 当前资产结论

| 资产 | 当前结论 |
|---|---|
| `academic-research-skills` | 本机目录为空，状态 `requested-but-unavailable` |
| `.codex/skills/academic-*`、`deep-research` | symlink，来源/版本需独立核验；若引用缺失则 `degraded` |
| `.agents/skills/nature-*`、`researchwrite` | 可读但多数无本地许可证；默认 `license_unknown`，不能直接再分发 |
| 用户 PDF | 18 页草稿资料，只作候选清单和设计启示，不作许可证或项目状态证明 |
| `pi-extensible-workflows` | 可借鉴协议；纳入前核对 npm tarball 的 MIT 声明与仓库许可证缺口 |
| `pi-workbench` | 有 tmux 公开项目和 Stella 桌面缓存，作为参考，不作为核心依赖 |

## 7. 准入流程

1. `discover`：记录名称、来源、路径和描述，不执行正文。
2. `inspect`：扫描许可证、依赖、脚本、网络/写盘能力、符号链接和 prompt injection。
3. `contract`：定义输入、输出、证据等级、失败状态和最少 fixture。
4. `trust`：用户批准范围；高风险能力单独批准。
5. `enable`：记录可用的版本/ref/SHA 信息，按需加载；缺失字段由模型补充或提示。
6. `verify`：通过 R0-R3 相关评测后才标 `verified`；失败则 `degraded/blocked`。
7. `update`：新版本重新审计和回归，不静默替换已锁定内容。
