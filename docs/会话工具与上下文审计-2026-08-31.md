## 2. 工具重复调用

| Pingouin Skill 安装 | 15 | 错误仓库尝试后自动换源；仓库结构、尺寸、manifest、依赖分多轮读取 |

这类调用没有协议层重复，却造成更严重的累积上下文成本：每次工具结果都会成为以后每一轮的历史输入。

### 5.3 为什么 cache read 达到 1,388 万

这不是存在 1,388 万个独立内容 token，而是长历史被 108 个 Assistant 回合反复读取的累计值。上下文从首轮约 11.7K 增长到末轮约 259K；最后 20 轮基本每轮都重读 213K-257K cached tokens。

直接成因按影响排序：

1. 单会话连续完成安装、配置解释、研究追问、分析、文献、写作、评审、DOCX 和 Export 定位。
2. 大量可保存在文件中的内部 thinking 被保留在会话树。
3. Shell 输出过长，尤其是完整 README、编译源码、Skill 正文和 API 返回。
4. Skill 描述索引常驻系统提示，重复来源会继续放大。
5. 任务拆成 121 次调用，每次新增内容又被之后所有轮次重读。

## 6. 优化策略

### P0：阶段边界和自动压缩

- 把安装、分析、文献、写作、评审、DOCX、Export 视为独立阶段。
- 每完成一个阶段，写一个 1-2K token 的结构化 handoff：目标、已确认事实、产物路径、关键数字、未决问题、下一步。
- 达到 40-60 次工具调用、100K context 或切换到重型阶段时，主动 compact；达到 150K 时建议新会话继续。
- compact 后保留 handoff、用户决定和产物引用，不保留详细 shell 输出与逐步推理。

预期收益最大，因为它直接消除后期每轮 200K+ 的历史重读。

### P0：Skill 摘要索引与按需正文

- `/skills` 继续发现所有项目级和用户级 Agent Skill，但系统提示只放规范化名称、单行短描述、来源和 scope。
- 同名 Skill 只将选中项放进 active descriptor；重复来源只显示计数，不把多份描述注入模型。
- Skill 正文只在路由命中或用户 `/skill <name>` 后加载一次，并记录 `discovered -> selected -> loaded -> completed/failed` 状态。
- 禁止模型为了使用外部 Skill 直接 `read .../SKILL.md`；统一通过一个可加载任意已发现 Skill 的工具，返回正文和来源。

### P0：按名称去重

- `scanLocalSkills` 和 `enabledLocalSkillPaths` 当前按路径去重，应改为规范化名称去重。
- 项目级优先于用户级，PsyClaw/Pi 显式目录优先于其他 Agent 用户目录；同优先级保持固定根目录顺序。
- 只有被选中的 Skill 路径传给 Pi ResourceLoader，避免 Pi 再把重复 descriptor 放进 `<available_skills>`。

### P1：任务专用聚合工具

- Skill 安装：一个安装调用完成 clone/download、collection 发现、复制和最小结构检查，返回紧凑结果；不让模型组织十几条 shell。
- 文献核验：一个批量工具接收 DOI/title 数组，一次查询多个来源并返回规范化表，单条来源失败不让整批崩溃。
- 环境诊断：一次返回平台、Python、Pandoc、python-docx 和关键依赖状态。
- Export 定位：命令直接返回输出路径和来源统计，不再让模型 grep 编译源码推断。

### P1：限制工具输出

- 默认只返回摘要、计数、错误和结果文件路径；详细输出写日志，按需读取片段。
- README/Skill references 先用目录或 heading 索引定位，再读取必要段落。
- 网络查询返回规范字段，不把原始 JSON 或多套相似题录全文带回上下文。
- 写文件成功以工具结果为准，不额外 `ls/cat` 验证；仅对关键产物做一次结构检查。

### P1：降低 reasoning 留存成本

- 复杂生成先把计划写成短结构，再分模块执行，避免一次 58K 字符内部推理。
- 工具回合使用较低 thinking；研究设计、结果解释和审稿阶段再提高。
- 阶段 handoff 只保存结论和证据，不保存完整内部推理。

## 7. 建议验收指标

- 同类完整演示控制在 50-70 次工具调用；安装单个 collection 不超过 3 次模型可见调用。
- 系统提示中 Skill 索引控制在 5K 字符以内；同名 Skill descriptor 只出现一次。
- 每个被使用 Skill 有 `selected/loaded/completed` 事件，安装但未加载的 Skill 不显示为 active。
- 工具 call/result 匹配率 100%，参数 schema 错误为 0。
- 单阶段结束上下文建议低于 100K；进入写作或评审前完成 compact/handoff。
- 文献批量核验中单来源字段缺失不使整批失败。

## 8. 当前判断

会话没有明显的工具协议故障，也没有参数传输丢失。性能问题主要来自模型用通用 shell 完成了本应由聚合工具完成的任务，加上 Skill 全量 descriptor 常驻、直接读取多个 Skill 正文、长 thinking 和跨七个阶段不压缩。优先优化阶段边界、Skill 去重/按需加载和聚合工具，比单独缩短最终回答更有效。
