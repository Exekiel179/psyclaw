# psyclaw 架构蓝图

## 1. 设计原则

1. **Pi 是底座，不是要被重写的对象。** 模型、会话、资源加载、Skill 渐进加载、Package、Extension、TUI 和 RPC 复用官方 Pi。
2. **领域逻辑以契约存在。** psyclaw 只负责研究项目、证据、门禁、状态、编排和审计；每个判断都尽量落成可测试的数据结构。
3. **默认最小权限。** 发现、读取、写入、联网、破坏性动作分级；外部能力默认关闭，副作用逐项审批。
4. **证据先于文字。** 先建立来源和 Claim-Evidence 关系，再生成摘要、设计或稿件；没有证据就明确缺口。
5. **失败闭合。** 验收条件未满足就暂停或标记 `blocked`，不以模型自然语言、模糊“可能正确”或漂亮格式绕过。
6. **人类保留决定权。** 完整性、伦理、外部发布、记忆晋升和高风险副作用都需要明确的人工检查点。
7. **社会科学可配置。** 证据等级、方法学术语和报告合同按研究范式配置，不照搬医学金标准。

## 2. 分层

```text
L0  Pi substrate
    AgentSession / ModelRuntime / ResourceLoader / Skills / Packages / ExtensionAPI
    Session JSONL tree / RPC JSONL / TUI
             |
L1  psyclaw domain core
    Project + Run, EvidenceLedger, Provenance, Gates, Workflow, Memory, Trust
             |
L2  research workflows
    research-brief, literature-review, analysis-delegation,
    qualitative, writing-review (按需加载)
             |
L3  skills / MCP / plugins / Python-R backends
    只声明能力和结果合同；具体计算或检索由成熟工具完成
             |
L4  projections
    Pi TUI widget + JSONL events -> future Web/Electron panel
```

L1 是 psyclaw 真正新增的最小面。L2-L4 可以迭代，不能反过来侵入 Pi session/model 核心。

## 3. 最小领域契约

所有边界使用 TypeBox/JSON Schema 校验；每个写盘记录带 schema version。以下是语义草案，字段名在 M1 固化。

```ts
type Effect = "read" | "write" | "network" | "destructive";
type EvidenceLevel = "metadata" | "abstract" | "snippet" | "fulltext" | "user";
type ClaimStatus = "supported" | "uncertain" | "unsupported";

interface ResearchProject {
  id: string;
  root: string;
  paradigm: string;
  goal: string;
  createdAt: string;
  policyVersion: string;
}

interface Evidence {
  id: string;
  source: { kind: string; locator: string; title?: string };
  level: EvidenceLevel;
  quote?: string;
  retrievedAt: string;
  sha256?: string;
  accessStatus: "verified" | "partial" | "unavailable";
}

interface Claim {
  id: string;
  text: string;
  evidenceIds: string[];
  status: ClaimStatus;
  uncertainty?: string;
}

interface Artifact {
  id: string;
  path: string;
  sha256: string;
  producedBy: string;
  inputIds: string[];
  reproducible: boolean;
}

interface GateResult {
  gateId: string;
  ok: boolean;
  severity: "block" | "warn";
  reason: string;
  evidenceIds?: string[];
}

interface ToolReceipt {
  schemaVersion: "psyclaw/tool-receipt/v1";
  runId: string;
  taskId: string;
  tool: string;
  effect: Effect;
  approval: "not-needed" | "approved" | "denied";
  idempotencyKey?: string;
  ok: boolean;
  reasonCode?: string;
  resultHash?: string;
  startedAt: string;
  finishedAt: string;
}

interface MemoryRecord {
  id: string;
  kind: "profile" | "decision" | "fact" | "lesson" | "evidence";
  scope: "session" | "project" | "user";
  content: unknown;
  sourceRefs: string[];
  confidence: number;
  status: "pending" | "active" | "archived";
}
```

原则：`Claim.status=supported` 必须存在可定位证据；`Artifact` 没有哈希或输入关系不能作为完成产物；`ToolReceipt` 缺审批或幂等信息时不能通过副作用验收。

### 3.1 Evidence sufficiency contract

`EvidenceLevel` 只描述材料形态，不自动等于“足够支持”。每条 Evidence 还必须通过当前研究范式的 `EvidencePolicy`：

```ts
type Relation = "supports" | "contradicts" | "context";

interface EvidenceLocator {
  kind: "doi" | "url" | "file" | "page" | "section" | "offset" | "row";
  value: string;
}

interface ClaimEvidenceLink {
  claimId: string;
  evidenceId: string;
  relation: Relation;
  locator?: EvidenceLocator;
  rationale: string;
}

interface EvidencePolicy {
  paradigm: string;
  claimKind: "existence" | "definition" | "method" | "result" | "interpretation";
  minimumLevel: EvidenceLevel;
  locatorRequired: boolean;
  requiresIndependentSource: boolean;
  requiresArtifactRun: boolean;
}
```

MVP 的机械判定：

- `metadata` 只能支持 `existence` 或题录字段；必须有 DOI/稳定 URL/用户文件路径之一。
- `abstract` 可支持摘要明确陈述的 `definition`/高层 `interpretation`，不能单独支持全文方法、数值结果或因果结论。
- `snippet` 必须有逐字引用和 `page/section/offset` locator；缺定位时最高只能是 `uncertain`。
- `fulltext` 必须有文件 SHA-256，并有页码/章节/结构化行号 locator；`user` 证据可以作为输入依据，但未独立核验时仍标 `uncertain`。
- `result` 或任何具体数值 Claim 必须同时引用真实 `Artifact`/`Run`（脚本、输入指纹、环境和结果哈希）；文献题录本身不能证明本项目的数值。
- 一个 `supported` Claim 至少有一条满足 policy 的 `supports` 链接；存在未处理的 `contradicts` 链接、缺必需 locator 或证据级别不足时，状态只能为 `uncertain`/`unsupported`，gate 为 `block`。

这些规则是最小默认值。社会科学 profile 可以放宽“独立来源”或更换 `claimKind`，但不得删除 locator、来源和不确定性要求。M1 必须把上述规则固化为纯函数与正反 fixtures，而不是只留在 prompt 中。

## 4. 项目布局与事实源

M1 已实现的对应入口为 `src/project/*`、`src/research/*`、`src/core/*` 和 `src/adapters/pi/extension.ts`；M2 增加 `src/skills/registry.ts`（descriptor-first、按需正文、冲突诊断）与 `src/orchestration/runner.ts`（schema Plan、只读 bounded executor、checkpoint/resume）。M3 增加 `src/integrations/mcp.ts`（`StdioMcpTransport` + `McpClient` 的 argv/显式 env/超时隔离，fake-bridge 可测）、`src/skills/preflight.ts`（恶意正文 tripwire）、`src/trust/manifest.ts` 与 `src/trust/sbom.ts`（CycloneDX 1.5 + 许可证审计摘要哈希）。M4 增加 `src/workflows/*`（`literature-review` / `analysis-delegation` / `writing-review` 三个复用 evidence 门禁的 workflow 包，共享 `finalizeWorkflow` 产物/verdict/handoff 尾段）。M5 增加只读 `RunSnapshot` 投影、窄 IPC panel server、Agents/Skills 与模型适配元数据页；`src/panel/extension.ts` 作为可选 Pi 扩展启动 loopback 面板，默认 package 不加载它。

```text
.psyclaw/
  project.json                 # 研究目标、范式、策略版本
  evidence.jsonl               # 来源与证据，append-only
  claims.jsonl                 # Claim 与支持关系，append-only
  runs/<run-id>.jsonl          # 事件、receipt、checkpoint、verdict
  memory/<scope>.jsonl         # pending/active/archive 记忆
  manifests/<artifact>.json    # 文件哈希、输入、环境
  manifests/<run-id>.verdict.json # 机器可读 pass/blocked 判定
  trust.json                   # Skill/MCP/Plugin 信任决策
  audit.jsonl                  # 权限和副作用审计
data/
  raw/                         # 只读；符号链接目标也拒绝
  clean/                       # 经研究者确认的派生数据
notes/                         # 交接、设计卡、解释性笔记
outputs/                       # 经过 gate 的交付物
```

`runs/<run-id>.jsonl` 是运行事实源；TUI/未来面板只消费事件和快照，不反向修改事实。所有 append 写入使用临时文件/锁或单写入者队列，避免并发 JSONL 损坏。

## 5. 工作流状态机

```text
planned -> intake -> executing -> awaiting-human -> verifying
                                      |                 |
                                   blocked <--------- failed
                                                        |
                                                   completed
```

每个 Step 声明：输入、输出、前置 gate、允许工具、effect、完成合同、是否可并行。恢复时必须校验 workflow version、目标摘要、输入哈希和已完成产物；不一致则从头或显式分支运行，不能静默复用旧结果。

### MVP `research-brief`

1. `intake`：生成研究问题、范式、范围、伦理和输出目标卡；缺关键字段暂停询问。
2. `capture`：导入本地 Markdown/PDF/DOI 元数据，记录来源、状态和 SHA-256；MVP 不自动抓任意 URL。
3. `ledger`：拆分 Claim，建立证据等级和支持/冲突/未知关系。
4. `audit`：执行引用、来源、文件、伦理和 AI 失败模式门禁。
5. `write`：只根据已验收证据写 `brief.md`，缺口显式标注。
6. `handoff`：写 `HANDOFF.md` 和机器可读 `handoff.json`，包含目标、完成项、验证命令、阻塞和下一步。

后续 workflow 必须复用这些 Step/contract，而不是为每个模式复制一套循环。

## 6. 编排与多智能体运行时

```text
ResearchRequest
      |
Planner (只产 schema-valid Plan，不调用工具)
      |
Scheduler (依赖、预算、并发、owned_paths)
      |
Executor(s) -> structured ToolReceipt / Artifact
      |
Verifier (只认 receipt、哈希、必需产物和证据)
      |
Finisher (只汇总已验收结果，不再调用工具)
```

首期 `maxWorkers=3`，绝对上限 4；并行 worker 只开放 read/search/parse 等只读能力。任何写入、网络上传、数据库变更或发布动作由主执行器串行完成并审批。未来若需要并行写入，必须每个任务独立 worktree/临时目录或 OS 容器隔离，再由 verifier 检查 diff 和 owned paths；prompt 中的“只写自己的目录”不是安全边界。

每个 `TaskNode` 至少有：`id`、`role`、`objective`、`deps`、`ownedPaths`、`parallelSafe`、`inputs`、`outputs`、`completionContract`、`budget`；可选 `allowedEffects` 只能由受信任协调器声明，省略时默认为 `read`。模型不能通过自然语言直接改变任务状态；状态变更只能来自 schema-valid `coordinator_action` 或 verifier 结果。

## 7. Pi 接入边界

- `src/adapters/pi/session.ts`：封装 `AgentSession`/`SessionManager`，不让业务代码依赖 Pi 0.x 内部类型。
- `src/adapters/pi/resources.ts`：复用 `DefaultResourceLoader`，实现 Skill progressive disclosure 和来源冲突诊断。
- `src/adapters/pi/model.ts`：封装 `ModelRuntime`/OpenAI-compatible provider；凭据只以环境变量引用存在，网络刷新默认关闭。
- `src/adapters/pi/extension.ts`：项目级 package 安装后注册少量研究命令和原生只读 `/agents` 多智能体入口；普通 Pi 对话在 psyclaw 功能故障时仍可用。
- `src/adapters/pi/rpc.ts`：多智能体 worker 使用严格 JSONL RPC 和显式环境/工具白名单；`src/panel/extension.ts` 是可选的 loopback 可视化入口。
- `package.json` 的 Pi manifest 是加载真源；可选 `package.json.psyclaw` 只放 `permissions/risk/evidence/license/ref/sha256` 治理元数据，不创建第二套插件机制。

## 8. MCP、Skill、Plugin

### MCP

MVP 只做 lazy stdio adapter：先发现和健康检查，再按 server 信任决定是否注册工具；工具名冲突确定性报错；超时、断线、重试、环境变量隔离和副作用 receipt 必须可测。HTTP/SSE/OAuth、浏览器和远程 server 后置。MCP 的 `env` 只能注入对应子进程，日志不得显示值。

### Skill

启动只载入 descriptor（名称、描述、来源、风险）；路由命中后才加载正文和 references。重复名称不静默择一；默认优先最窄、最相关且证据等级最高的 Skill。Skill 只能提出建议和工具意图，不能绕过 psyclaw gate。

### Plugin

Plugin 就是 Pi package/extension，不再造 runtime。安装前检查项目/用户信任、来源 ref、哈希、许可证、依赖和能力清单。因为 Pi extension 与宿主同权限，应用层 allowlist 不等于 OS sandbox；高风险插件需容器或独立进程。

## 9. 记忆与跨会话

首期只实现 project profile、decision、fact、lesson、evidence 五类记录。新记录先 `pending`，包含来源和置信度；研究者批准后才进入 `active`。冲突不覆盖旧值，而是保留两条记录并标记冲突。`lesson` 只有重复出现、通过已知/前向/对照/边界任务后才可晋升为稳定 Skill 规则。绝不把原始被试资料、凭据或整篇未发表稿件默认写进长期记忆。

## 10. 社会科学方法学 profile

内置 profile 初始包括：实验/准实验、调查/观察、纵向/面板、元分析、质性/主题分析、民族志、历史/文献、政策/法律、混合方法。Profile 只改变证据层级、术语和必需报告字段，不改变“可追溯、可复核、诚实标注”的底线。

每个 profile 至少声明：`evidencePolicy[]`、伦理/同意字段、必需方法记录、允许的结论动词、探索/确证标记和一个通过/阻断 fixture。首批只实现 `survey-observational` 与 `qualitative-thematic` 两个 profile；其他 profile 先以 `degraded` descriptor 出现，避免伪装成已完成的方法学支持。

通用检查包括：

- 适用时报告效应量、区间估计、样本量、缺失处理和假设检查；统计数值必须来自真实运行的外部工具。
- 区分探索性/确证性，识别 p-hacking、HARKing、选择性报告和把相关写成因果。
- 人类受试者、敏感资料、同意、伦理审批、匿名化、数据可用性和利益冲突必须有状态。
- 显示语言/地区/数据库覆盖和影响因子偏差；不把英语高影响期刊当作唯一知识来源。
- 质性研究保留研究者立场、编码轨迹、反身性和反例；不强行套量化证据金字塔。

## 11. 面板演进

MVP 面板 = Pi TUI 顶部状态 widget + `.psyclaw/runs/*.jsonl` 事件流，展示当前阶段、gate、等待人工事项、产物和证据覆盖率。`src/panel/projection.ts` 固化 `RunSnapshot` TypeBox schema 并做只读、脱敏投影；`src/panel/server.ts` 提供窄 IPC（`/api/runs`、`/api/snapshot`、`/api/catalog`、`/api/install-plan`、`/api/import-plan`）的只读 HTTP 面板，`apps/panel/index.html` 为零构建静态渲染层，`psyclaw serve` 或可选 `src/panel/extension.ts` 启动。面板不能成为第二个事实源，也不能让渲染层直接调用 MCP/文件系统；安装和导入链接只展示审批前计划，不执行副作用。

## 12. 从 PsyClaw 迁移

| PsyClaw 经验 | psyclaw 落点 |
|---|---|
| Router -> Workflow -> Step -> Skill/MCP | `WorkflowSpec` + Pi ResourceLoader + Integration adapter |
| Planner -> Scheduler -> Executor -> Verifier -> Finisher | `orchestration/*`；首期单 Executor，接口先行 |
| evidence/claim/provenance sidecar | `EvidenceLedger`、`Artifact`、`manifest.json` |
| fail-closed gates 与 7 类 AI 研究失败 | `Gate` profile + `Verdict` |
| project/session/lesson memory | append-only `MemoryStore` + approval policy |
| material conversion / handoff | 可选 converter adapter + `HANDOFF.md` contract |
| 外部统计/MCP | Python/R/MCP integration，不把算法移入 TS core |
| evalharness | fixtures + fake bridge + security adversarial evals |

迁移只搬“数据契约、判据、反模式、测试思想”；不复制旧 CLI、统计模块、全量 prompt 或与 Pi 重叠的 REPL。
