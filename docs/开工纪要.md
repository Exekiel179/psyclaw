## 1. 使命

为社会科学人员提供一个开箱即用、便捷、准确、高效且聪明的科研智能体。它应能从研究目标出发，逐步完成资料整理、证据检索与核验、研究设计、分析委托、写作和复核，同时始终保留研究者的判断权、可复现证据和可追溯过程。

产品代号为 `psyclaw`。它保持 Pi 的“少即是多”：核心只增加科研领域真正需要的契约和编排，不复制 Pi 已有的模型、会话、Skill、Package 或 TUI/RPC 实现。

## 2. 现状基线

- 本工作区只有 Git 初始提交，没有可继承的 psyclaw 源码、README 或项目记忆。
- `F:\Projects\psyclaw` 是领域规格和行为经验的主要来源，已有文献、证据、门禁、工作流、记忆、MCP 和离线评测实现；psyclaw 将迁移其契约和原则，不整体复制 Python 实现。
- 本机缓存了 `pi-extensible-workflows` 与 Stella `pi-workbench` 源码；它们用于参考协议和边界，不作为 psyclaw 的运行时依赖。
- 当前 Pi 为 `@earendil-works/pi-coding-agent` 0.84.1。Node 22.19+ 是发行基线；本机 Node 25 只作兼容性验证，不作 CI 基线。
- `academic-research-skills` 目录为空；多项 academic/nature Skill 缺许可证、来源或共享依赖，不能直接宣称已内置或已验证。

## 3. 目标与可验收结果

### 目标

1. 新用户在干净项目中可以用自然语言建立研究项目并得到下一步建议，不必记忆一套新命令。
2. 任何事实性 Claim 都能回溯到来源、证据等级、获取时间和必要的文件哈希。
3. 工作流可以暂停、恢复、审计；失败、缺证据、冲突或越权时快速失败，而不是“尽力编完”。
4. 外部 Skill、MCP、Plugin 可按需接入，但权限、许可证、版本、依赖和风险可见。
5. 多智能体能减少等待而不牺牲可控性；并行任务不共享无保护写目录，结果必须经过结构化验收。
6. 面板先以 Pi TUI widget + JSONL 事件投影提供运行状态，后续再独立发展 Web/Electron 面板。

### 首个可交付切片（MVP-0）

离线 `research-brief`：

`研究目标 -> intake card -> 导入本地 Markdown/PDF/DOI 元数据 -> SHA-256/provenance -> Claim-Evidence 账本 -> 引用/完整性审计 -> brief.md + manifest.json + verdict.json -> HANDOFF.md`

限制：单执行器、无默认联网、无并行写入、无统计数值计算、无自动投稿。该切片必须能在没有真实 LLM 和网络的情况下由 fixtures 重放并通过结构化评测。

## 4. 明确不做

- 第一阶段不 fork 官方 Pi，不维护第二套 session、provider、skill 或 plugin runtime。
- 第一阶段不把几十个第三方 Skill 的正文复制进仓库，不把缺许可证或缺依赖的 Skill 标为可用。
- 不在 psyclaw 内重写 pandas/scipy/statsmodels 等统计算法。
- 不绕过付费墙、验证码、机构认证，不读取或导出密码、Cookie、Token。
- 不把模型生成的“已完成”当作事实；不自动把未经人工验收的论文、图表或数据发布到外部平台。
- 第一阶段不构建大型 Kanban、Autopilot、浏览器自动化中心或 35MB 级科研绘图资产包。

## 5. 关键技术决策

| 决策 | 选择 | 原因 | 放弃的选项 |
|---|---|---|---|
| Runtime | 官方 Pi 0.84.1，TS/ESM adapter | 保留 Pi 的极简和生态，隔离 0.x API 变动 | fork omp / 自建 Agent runtime |
| 包形态 | 一个 psyclaw package + Pi extension；可选 `package.json.psyclaw` 治理元数据 | 复用 Pi package 真源，不新造 plugin runtime | 独立大型平台先行 |
| 状态 | 项目内 append-only JSONL + 原子 manifest | 易审计、易迁移、无数据库门槛 | 首期引入 SQLite/向量库 |
| 多智能体 | typed Plan -> bounded Scheduler -> Executor -> Verifier | 让并行可验证、可恢复、可限预算 | 只靠自然语言委派 |
| 面板 | 事件协议 + Pi TUI widget，Web/Electron 后置 | 先提供可见性，不绑定 UI 技术 | 先造完整桌面应用 |
| 统计 | 外部成熟库/MCP，保存脚本和环境 | 与 PsyClaw 学术边界一致 | 核心内置统计算法 |

## 7. G0 需要确认的默认值

本规划采用以下默认值继续细化：

- 发行平台：Windows/macOS/Linux；CI 只承诺 Node 22 LTS，Python sidecar 先承诺 3.12/3.13。
- 默认入口：保留 `pi` 原生入口；提供 `psyclaw` 作为安装/诊断/研究项目 bootstrap 的薄 CLI，而不是第二个聊天入口。
- 默认核心 Skill：`research-intake`、`evidence-capture`、`citation-audit`、`research-brief`，必要时加 `analysis-plan`；启动不加载全文。
- 默认网络：发现不等于执行；MVP 离线优先，学术 API 作为显式启用的只读适配器。
- 默认记忆：项目级 profile/decision/lesson/evidence，写入先 `pending`，需人工批准后才跨会话生效。
- 默认许可证：实现代码暂按 MIT 规划；第三方内容遵循其自身许可证，未经核验不再分发。

若这些默认值没有被修改，G0 后按 M1 开始实现；若需要改变包形态、平台或默认联网策略，应先更新本纪要并重新评估安全与评测范围。
