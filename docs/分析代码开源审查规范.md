# 分析代码开源审查规范

psyclaw 生成的分析项目不得把数据读取、清洗、统计、校验和导出塞进一个不可审查的脚本。入口文件只负责编排，实际步骤必须拆成独立模块。

```text
analysis/
├─ scripts/
│  └─ <claim-id>/
│     ├─ README.md          # 研究问题、输入、假设、环境、运行顺序和限制
│     ├─ 01_load.py        # 只读加载与输入哈希
│     ├─ 02_prepare.py     # 派生数据、清洗和排除规则
│     ├─ 03_analyze.py     # 委托成熟 Python/R/SPSS/Mplus 库执行分析
│     ├─ 04_validate.py    # 结果门禁、敏感性检查和完整性检查
│     ├─ 05_export.py      # 图、表和机器结果导出
│     └─ run_<claim-id>.py # 薄入口，只编排上述模块
├─ configs/                # 变量字典、参数和预注册快照
└─ results/                # psyclaw/analysis-result/v1 机器结果
```

审查最低要求：

- `data/raw` 只读，所有派生数据写入 `data/clean` 或 `artifacts/data`。
- 每个模块声明输入、输出、依赖和副作用；模块之间通过明确的数据结构交接。
- 入口脚本不得包含统计实现；统计委托成熟库或受信任 MCP。
- `01_load.py` 记录输入 SHA-256，`04_validate.py` 记录缺失值、效应量、不确定性和多重比较处理。
- `05_export.py` 只写入 `artifacts/` 或 `outputs/`，不得覆盖原始数据。
- README 必须给出一条可复现命令、环境版本、已知限制和人工决策点。
- 每个模块都可以单独阅读、审查和替换；任何失败都应阻断最终报告，而不是由入口脚本吞掉。
