# psyclaw 产物目录规范

项目初始化后，科研文件按生命周期和用途进入固定目录。智能体不得在项目根目录或任意临时位置散落写入。

```text
project/
├─ data/
│  ├─ raw/                         # 原始资料，只读；禁止覆盖、删除、重编码
│  └─ clean/                       # 研究者确认后的派生数据
├─ analysis/
│  ├─ scripts/                     # Python/R/SPSS/Stata/Mplus 可复现脚本
│  ├─ configs/                     # 分析方案、变量字典、参数与预注册快照
│  └─ results/                     # 机器可读分析结果、模型摘要、输入指纹
├─ artifacts/
│  ├─ figures/                     # PNG/SVG/PDF 等图形
│  ├─ tables/                      # CSV/TSV/XLSX/LaTeX/Markdown 表格
│  ├─ reports/                     # 中间报告、审阅稿、导出草稿
│  ├─ data/                       # 分析生成的派生数据包
│  └─ code/                       # notebook、辅助代码和环境锁定文件
├─ outputs/                       # 对用户交付的最终文件；index.json 是唯一索引
├─ notes/                         # 计划、HITL 决策、交接与人工审阅
├─ logs/                          # 人类可读日志
└─ .psyclaw/                        # 运行事实、证据账本、manifest、verdict、审计
```

规则：

- `data/raw` 永远只读，任何清洗或重编码写入 `data/clean`，并记录输入哈希。
- 图、表、代码和报告先写入 `artifacts/*`，通过 verifier 后再复制或导出到 `outputs/`。
- 每个产物都要进入 `outputs/index.json` 或对应 manifest，包含版本、SHA-256、输入和生成任务。
- 分析方案使用 `analysis-plan-vN`，论文审阅/修改使用 `writing-review-vN`；版本分配记录在 `.psyclaw/versions.jsonl`。
- 临时文件只能放在 `.psyclaw/runs/<run-id>/tmp`，运行结束后不得作为交付物暴露。
- 用户自然语言不需要记忆这些路径；工作台和工具契约负责路由。
