# psyclaw 威胁模型（M0）

范围：本地 Pi + psyclaw extension、项目目录、可选 Skill/Plugin/MCP、Python/R sidecar 和未来只读面板。此文档不包含任何凭据值。

## 资产与信任边界

| 资产 | 需要保护的性质 | 边界 |
|---|---|---|
| `.psyclaw/data/raw`（兼容旧 `data/raw`）、未发表稿、被试资料 | 不被修改、不外传、可追溯 | 项目文件系统 -> Agent/外部工具 |
| Evidence/Claim/Artifact ledger | 完整性、来源和版本 | 文件 -> 模型上下文/面板 |
| API key、Cookie、机构会话 | 保密 | 宿主环境 -> MCP/模型子进程 |
| run/checkpoint/handoff | 不被迟到结果覆盖、可恢复 | Executor -> JSONL事实源 |
| Skill/Plugin/MCP代码 | 供应链和权限 | 外部来源 -> Pi trusted host |
| 面板事件 | 脱敏、只读、一致 | JSONL事实源 -> UI/IPC |

## 主要威胁与控制

| 威胁 | 控制 | 评测案例 |
|---|---|---|
| 论文/网页 prompt injection | 外部文本永远是数据；不能改变系统策略、工具 allowlist 或任务状态 | `prompt-injection-paper` |
| 路径穿越/符号链接逃逸 | canonical path、拒绝 symlink target、项目根 allowlist、`.psyclaw/data/raw` 与旧 `data/raw` 永拒写 | `path-traversal`, `symlink-escape` |
| Skill/Plugin 执行恶意脚本 | discover-only、来源/ref/SHA/SPDX/SBOM、能力清单、用户信任；高风险独立进程/容器 | `malicious-skill`, `plugin-unknown-license` |
| MCP 凭据或数据外泄 | argv 而非 shell、显式 env、子进程隔离、日志脱敏、上传默认拒绝 | `mcp-env-isolation`, `credential-in-log` |
| 伪造引用/结果 | Evidence sufficiency、Claim status、artifact/run 绑定、fail-closed verifier | `unsupported-claim`, `fake-pdf-html` |
| 副作用重复执行 | receipt + idempotency key + 超时人工核对 + 不盲目重放 | `duplicate-side-effect` |
| 并发写损坏/迟到覆盖 | 单写入者、原子追加、attempt/specRevision、旧结果丢弃 | `stale-attempt`, `parallel-read-only` |
| 面板泄露或改写事实 | 只读 projection、窄 IPC、脱敏字段、断线不回写 | `panel-projection` |
| 社会科学方法偏见 | paradigm profile、语言/地区偏差披露、质性反身性与反例字段 | `social-paradigm-profile` |

## 保护机制全景

PsyClaw 的保护不是一个总开关，而是分布在输入、执行、文件、证据、生态和展示边界上的多层控制。下表按实际责任划分，便于排查某次阻断究竟来自哪里。

| 保护层 | 防护对象 | 主要机制 | 典型结果 |
|---|---|---|---|
| 指令边界 | 论文、网页、Skill 等材料中的提示注入 | 外部内容只作为数据；不能改变策略、工具白名单或任务状态 | 忽略材料内指令，保留材料本身 |
| 受控运行授权 | `/run` 中的常规副作用与外部操作 | 计划内普通写入自动记账；外部投稿、发信等另行确认 | 自动批准并记录，或等待明确确认 |
| 项目路径 | 越界路径、`.git`、原始数据、凭据路径、符号链接逃逸 | 规范化项目相对路径、真实路径解析、protected path 检查 | 写入前拒绝不安全目标 |
| 编排所有权 | 并行冲突、worker 越权写入 | `ownedPaths`、effect allowlist、只读并行、单写入者 | 拒绝未声明写入或路径重叠 |
| 副作用一致性 | 重试造成重复安装、下载、提交或修改 | approval、receipt、幂等键、超时后不盲目重放 | 去重、阻断或转人工核对 |
| 证据完整性 | 引用幻觉、结果幻觉、把摘要冒充全文 | Evidence policy、locator、文件哈希、Claim-Evidence 链、verifier | 降级为 `uncertain` 或阻断交付 |
| 恢复一致性 | 旧 checkpoint、迟到 worker 覆盖新状态 | 输入哈希、plan hash、workflow version、attempt、specRevision | 漂移时拒绝复用 |
| 生态准入 | 恶意或来源不明的 Skill、Plugin、MCP | discover-only、来源/ref/SHA/许可证/依赖检查、显式启用 | 只发现不执行，或阻断加载 |
| 凭据与网络 | key、Cookie、机构会话泄露 | 显式 env 注入、argv 启动、日志脱敏、上传默认拒绝 | 子进程最小可见、输出脱敏 |
| 展示投影 | 面板泄露敏感信息或反写事实源 | 只读 projection、窄 IPC、敏感字段脱敏 | UI 只能读取受限快照 |
| 学术方法 | 不适用的方法门槛、探索冒充确证、相关写成因果 | paradigm profile、报告合同、分析 hooks | 警告、补充报告或阻断结论 |

### 已移除的内容关键词写入守卫

2026-09-05 移除了 Pi `tool_call` 钩子中的 `autoApprovalBlocked`。该守卫把整个工具输入序列化后搜索 `data/raw`、`credential`、`secret` 等文本，并据此拒绝 `write`、`edit`、`bash` 和 `powershell`。因此，写入普通报告时只要正文提及原始数据路径、`.sav` 文件或凭据规则，也会被误判为正在覆盖原始数据或接触凭据。

移除后，正文内容不再参与写入授权判断，`/run` 内的普通写入按范围授权执行并记录 approval。项目自身的结构化写入路径仍由 `assertSafeProjectPath`、scheduler 路径声明、installer 目标检查和 worker completion verifier 保护；这些机制判断实际目标路径和结构化副作用，而不是扫描正文关键词。

需要明确的是：Pi 内建通用 `write`、`edit`、`bash`、`powershell` 工具与 PsyClaw 自有写入 API 不是同一个执行边界。删除该钩子后，PsyClaw 不再用内容关键词提前拦截这些通用工具；它们的文件系统限制取决于 Pi 宿主、操作系统沙盒及当前会话权限。应用层保护不应被表述为 OS 级隔离。

## 残余风险

- Pi extension 与宿主同权限；应用层权限不是 OS sandbox。需要强隔离时必须使用容器/独立用户/受控执行器，并记录环境。
- 真实机构登录、浏览器自动化、第三方 MCP 和模型服务的安全性不能由离线评测完全证明；它们只能 opt-in，并保留人工检查点。
- Node/Pi 0.x API 可能漂移；精确版本、lockfile、adapter contract test 和升级回归是发布前条件。
- 影响因子、英语数据库和公开论文样本会造成社会科学知识偏差；结果应披露覆盖范围，不把排序当作真理。
- 安装/下载：staging、SHA 门禁与幂等 ledger 是应用层控制，不等于对真实 registry/供应链的证明；真实下载仍需来源 ref/版本 pin 与独立核验。
- Skill 导入：源文件采用「单次读取 → 哈希 → 写回同一字节」降低 TOCTOU，但无法在应用层消除 read 与 copy 之间的竞态；强隔离需 OS 级 fd 锁定或不可变快照。
- worker 隐匿副作用：`filesModified` 与 receipt 是执行器自报，不能检测未声明的写盘/网络/破坏性动作；应用层 lease 不是 OS sandbox，需容器/独立进程隔离。
- 面板篡改：面板是 `.psyclaw/runs/*.jsonl` 与 checkpoint 的只读投影，事件日志是追加事实源，但本地进程可篡改 JSONL；这不构成对抗本地攻击者的边界，只防「看起来完成」的误导。

## 处置规则

任何 P0 风险都将 run/release 标为 `blocked`。只有记录原因、影响范围、人工决定和后续验证后才可继续；“模型认为安全”不是解除阻断的依据。
