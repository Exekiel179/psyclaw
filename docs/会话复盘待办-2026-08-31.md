## 1. 已确认的产品决定

### 1.1 普通模式

- 普通模式允许直接分析数据、运行脚本、写分析报告和论文草稿。
- 普通模式产物不强制标记为 `draft` 或 `unverified`。
- 不新增必须先执行 `/run` 才能分析或写作的限制。
- `/run` 继续用于需要项目状态、证据账本、可恢复工作流和结构化验收的场景，不垄断普通研究协作。

### 1.2 统计结果与责任提示

- 不为本次复盘新增“显著性措辞”、置信区间或模型比较的硬阻断规则。
- 优化系统提示：分析结果和模型生成内容可能存在错误，正式使用前应由用户审核。
- 完成审核不等于系统担保正确；研究结论、稿件内容和最终提交仍由用户负责。
- 提示应简短、清楚，不在每一段重复，也不妨碍正常分析流程。

### 1.3 DOCX 验证

- 保留当前结构验证：文件可打开、图片已嵌入、文字/标题颜色、表格边框和基本版式检查。
- 不把 DOCX 转 PDF、逐页截图或视觉回归设为普通导出的必需步骤。

### 1.4 Export 与 Trace

- `/trace` 命令保持删除，不恢复、不提供别名。
- `/export` 完全使用 Pi 内置会话导出能力，PsyClaw 不再提供平行实现。
- Panel 只展示 Export 内容，不再出现 Trace 入口、Trace 页面或 Trace 文案。

## 2. Skill 安装精简

目标：让 Skill 安装接近“选择来源 -> 选择项目级或用户级 -> 安装 -> reload”，不增加额外验证负担。

### 2.1 删除重型可信安装机制

- 删除 Skill 安装对 immutable ref、内容 SHA、许可证审计、依赖审计、SBOM、admission evidence、安装 receipt 和幂等账本的强制要求。
- 删除只服务于上述 Skill 安装机制的类型、实现、UI 字段、测试和文档。
- 不误删 MCP 副作用审批、通用路径保护、凭据保护和研究工作流 receipt；这些不是本次 Skill 安装精简范围。
- 删除前先梳理 `src/install/installer.ts`、`src/skills/contracts.ts`、`src/skills/registry.ts`、`src/trust/*` 的调用关系，区分 Skill 专用代码与其他功能复用代码。

### 2.2 最小安装行为

- 用户明确发起安装后，允许从给定目录或 Git 仓库获取 Skill。
- 保留最小结构检查：目标中能发现至少一个带有效 `name` 的 `SKILL.md`。
- collection 仓库递归发现多个 Skill；单 Skill 仓库直接加载其 Skill 目录。
- 保留基本路径边界：不写 `data/raw`、`.git` 或项目外的非目标目录，不跟随符号链接写入。
- 来源不存在、来源被搜索结果替换、或安装作用域发生变化时，必须向用户说明并取得确认；不能自动把 `agent-res/...` 改成另一个仓库，也不能自动把项目级改成用户级。
- 安装失败时保留已有文件，不伪造 `SKILL.md`。

### 2.3 Supervisor-Skills

- 将 `skills/recommended/catalog.json` 中 `supervisor-skills` 标记为 collection，或让安装器根据多个 `SKILL.md` 自动识别 collection。
- 安装后 `/skills` 应列出实际子 Skill，而不是要求不存在的根级 `SKILL.md`。

## 3. Skill 检索与重复处理

目标：实现一个简单、本地、确定性的检索器；只负责发现和选择，不引入许可证或供应链准入流程。

### 3.1 搜索目录

同时检索项目级和当前用户下其他 Agent 工具的 Skill：

- 项目：`.claude/skills`、`.claude/commands`、`.codex/skills`、`.agents/skills`、`.opencode/skills`、`.cc-switch/skills`、`.psyclaw/skills`、`skills`。
- 用户：`~/.claude/skills`、`~/.claude/commands`、`~/.codex/skills`、`~/.agents/skills`、`~/.opencode/skills`、`~/.cc-switch/skills`、`~/.psyclaw/skills`。其中 `.claude/commands/*.md` 作为斜杠命令逐文件加载，不再把整个 `commands` 目录误当成一个 Skill。
- Pi/PsyClaw 管理目录：`getAgentDir()/skills` 和项目 `.psyclaw/imports/recommended`。
- 可选扩展：`PSYCLAW_SKILLS_PATH`。

不扫描整台电脑，不读取其他用户目录，不扫描隐藏缓存、`.git` 或 `node_modules`。

### 3.2 简单发现规则

- 有 `SKILL.md` 的目录就是一个 Skill；最多递归固定深度。
- 只解析 YAML frontmatter 中的 `name` 和 `description`，正文按需读取。
- 记录 `name`、`description`、`path`、`source tool/root`、`scope`。
- 目录不可读或 frontmatter 无效时跳过并给一条诊断，不阻断其他 Skill。

### 3.3 同名去重

- 规范化 Skill 名称后按名称去重，不再只按路径去重。
- 默认只加载一个同名 Skill，优先级固定为：项目级显式来源 > 项目级其他来源 > 用户级 PsyClaw/Pi > 用户级其他 Agent 来源。
- 同一优先级按搜索目录顺序稳定选择，不能随文件系统遍历顺序变化。
- `/skills` 显示被选中的来源和重复数量；需要时可展开查看被忽略路径。
- 重复不是错误，不要求用户逐个处理，也不重复加载正文。
- `/run` 任务仍可显式选择某个 Skill；选择只作用于该 run，不改变全局启用状态。

实现进度（2026-08-31）：已按固定目录顺序选择首个同名 Skill，保留被忽略路径供 `/skills` 汇总；运行时只传递存在的绝对 Skill 路径，并排除核心同名项。待运行定向测试与真实启动验收。
